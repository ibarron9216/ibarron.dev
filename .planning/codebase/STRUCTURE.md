## Directory Purposes

**Root HTML Files:**
- Purpose: User-facing pages.
- Contains: One file per top-level route.
- Key files: `index.html`, `research.html`, `teaching.html`, `students.html`, `contact.html`.

**`css/`:**
- Purpose: Shared CSS for all pages.
- Contains: `style.css`.
- Key files: `css/style.css`.
- Subdirectories: None.

**`js/`:**
- Purpose: Shared browser behavior.
- Contains: `main.js`.
- Key files: `js/main.js`.
- Subdirectories: None.

**`assets/`:**
- Purpose: Static non-code assets.
- Contains: `assets/cv.pdf` and `assets/fonts/inter-variable.woff2`.
- Subdirectories: `assets/fonts/`.

**`.planning/`:**
- Purpose: GSD project management artifacts.
- Contains: `PROJECT.md`, `REQUIREMENTS.md`, `ROADMAP.md`, `STATE.md`, phase plans, research, and this codebase map.
- Key files: `.planning/PROJECT.md`, `.planning/STATE.md`.

## Key File Locations

**Entry Points:**
- `index.html`: Home page and primary site entry.
- `research.html`: Research content and external research links.
- `teaching.html`: Course listings and teaching philosophy.
- `students.html`: Most interactive page; uses sidebar navigation and accordion behavior.
- `contact.html`: Email, office, address, and profile links.

**Configuration:**
- `.planning/config.json`: GSD workflow configuration.
- `css/style.css`: CSS custom property design tokens.
- No app runtime or build configuration files are present.

**Core Logic:**
- `js/main.js`: All JavaScript behavior.
- `css/style.css`: All component/layout behavior that is CSS-driven.

**Testing:**
- No test files or test directories.
- Historical verification reports are under `.planning/phases/`.

**Documentation:**
- `CLAUDE.md`: AI agent working conventions for this repo.
- `.planning/PROJECT.md`: Project requirements, constraints, and decisions.
- `.planning/codebase/*.md`: Generated codebase reference documents.

## Naming Conventions

**Files:**
- Top-level pages use lowercase descriptive names: `research.html`, `teaching.html`, `students.html`, `contact.html`.
- Shared assets use directory-based grouping: `css/style.css`, `js/main.js`.
- Planning artifacts use uppercase Markdown names in `.planning/`.

**CSS:**
- BEM-like class naming is dominant: `.nav__inner`, `.card-ur__title`, `.course-media-card__content`.
- Modifier classes use double hyphen: `.section--navy`, `.btn--primary--inverse`, `.card-ur--no-hover`.
- Utility or page-section classes are grouped by numbered CSS sections.

**JavaScript:**
- Functions use camelCase with an `init` prefix for setup routines.
- DOM state is coordinated through classes, `hidden`, and ARIA attributes.

## Where to Add New Code

**New Page:**
- Add a new root-level `.html` file.
- Copy and update the shared nav/footer shell.
- Link `css/style.css` and `js/main.js`.
- Add the page to every nav menu and set `aria-current="page"` only on that page.

**New Styles:**
- Add to `css/style.css`.
- Prefer extending existing component sections or adding a clearly labeled new section.
- Reuse `:root` tokens before introducing new colors or spacing values.

**New Behavior:**
- Add a new guarded initializer in `js/main.js`.
- Call it inside the existing `DOMContentLoaded` callback.
- Use semantic attributes and avoid requiring JS for core content visibility where practical.

**New Assets:**
- Put fonts under `assets/fonts/`.
- Put downloadable documents under `assets/`.
- Reference assets with relative paths from HTML or CSS.
